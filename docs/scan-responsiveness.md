# 大图库扫描与预览响应性

目标：处理 100GB 以上图库时，让窗口保持可操作，并按可见内容控制解码和传输开销。总文件容量、文件数量、单张像素尺寸是三种独立压力。

## 实现与取舍

- 扫描和缩略图/预览解码在后台 blocking 任务执行；图像解码共用两个并发名额。
- 先枚举文件，再读取元数据和配对。EXIF 单次解析时间、相机字段及配对标识，配对不再重新打开图片。JPEG XMP 按段读取，找到 XMP 或遇到图像载荷即停止，最多读取 512KiB。合并视频用 retain 一次过滤。
- 扫描进度每 100ms 上报，阶段边界强制发送；最终文件记录每批最多 256 条经 onFiles Channel 传输，不再单次传送全库 JSON。前端分批让出事件循环后提交列表。
- 初始预热最多 48 项，其余按可见区域加载。缩略图队列最多 4 个在途、256 个等待；预览队列最多 1 个在途、8 个等待。共享路径去重，离屏取消尚未开始的请求。
- 侧栏和大图使用最长边 2048px 的预览，先显示 320px 缩略图，100ms 防抖。大图只保留当前附近的胶片和预览，关闭清理。取舍是默认浏览不再直接加载全分辨率原图；视频仍由用户播放。
- 通用解码设置 256MiB 分配预算，JPEG 设置输出及渐进系数预算；Windows WIC 在 CopyPixels 前缩放，应用层只分配目标尺寸像素。JPEG 和通用解码保留 EXIF 方向，更新缓存键版本。
- 请求代次隔离取消、旧进度和旧预热。刷新保留期间最新标记/移除状态；失败保留原列表并可重试。已开始的系统文件读取/原生解码不能强制中断，结束后丢弃过期结果。

首次打开与后台刷新共用 ScanProgress.vue，参数为 progress、compact。查找时展示不定进度和数量，其余展示阶段内百分比。沿用现有 accent、bg-card、bg-panel、text-primary/secondary token；进度具备可访问名称，取消使用原生按钮，检查了 1280×800 和 390×844 扫描布局。

## Windows 待验收与边界

在 Windows 使用至少 100GB 的真实 JPG/HEIC/RAW/视频目录，分别验证冷缓存和热缓存：扫描、配对、预热、跳过预热后拖动/缩放/最小化窗口；快速滚动、切换大图、取消后马上打开另一目录，确认无“未响应”和旧进度覆盖。刷新期间标记文件，确认刷新后保留。网络盘/慢盘单独验收。

WIC 第三方编解码器的内部内存与方向处理仍需真实 Windows 验证；256MiB 是解码分配检查预算，并非整个进程的内存硬上限。超出安全预算或缺少解码器时会回退为占位预览。扫描索引仍随文件数量增长；临时磁盘缓存尚无总容量清理策略。此次未修改实况照片嵌入视频协议，超大嵌入视频的读取另需验证。
